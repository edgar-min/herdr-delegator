# 소통

작업자 질문에는 해당 레인 보고서에 `[ORCH Response]`를 추가한 뒤 알린다. 방향이 있는 동료 채널은 사용 전에 승인한다. 다른 run과 소통할 때는 이 run의 상대방 지정 채널에 먼저 기록하고 `notify_run`을 호출한다. 동료끼리 사실은 교환할 수 있지만 범위나 권한을 바꿀 수는 없다.

ORCH가 작업자 보고서에 쓰는 내용은 `[ORCH Response]` 블록뿐이다.

## 피어 통신, 재설정, 인계

계획에서 승인된 방향성 워커 채널만 사용한다. 피어들은 사실, 준비 상태, 의존성, 정숙 구간, 호환성 관찰을 공유할 수 있다. 범위, 소유권, 우선순위, 승인 또는 완료 조건을 재협상할 수는 없다.

다른 실행과 통신하려면 이 실행에서 해당 실행을 수신자로 지정한 채널에 추가한 뒤 그 실행의 ORCH에 알린다. 상대는 자체 역방향 채널에서 답한다. 각 측은 자신이 수락한 합의를 기록한다. 승인받지 않은 자원 소유권 주장은 합의가 아니다.

재설정이나 인계는 별개의 실행과 별개의 ORCH 생성 기록을 만든다. 계획 컨텍스트는 진실이 아니다. 대상은 상속된 증거에 의존하기 전에 이를 다시 검증한다. 활성 상태이거나 안전하지 않은 소스 레인은 보존하고, 안전하게 종결되었다는 사실을 새롭게 입증한 상태만 닫는다.


## 소통, 복구, 완료

작업자 질문에는 해당 레인 보고서에 `[ORCH Response]`를 추가한 뒤 알린다. 방향이 있는 동료 채널은 사용 전에 승인한다. 다른 run과 소통할 때는 이 run의 상대방 지정 채널에 먼저 기록하고 `notify_run`을 호출한다. 동료끼리 사실은 교환할 수 있지만 범위나 권한을 바꿀 수는 없다.

복구 전에 상태를 조사한다. 효과가 입증된 지점에서 이어가고, 효과가 없었음이 입증된 뒤에만 재시도한다. 모호한 좌표는 보존한다. 마운트된 예산·revival·close 연산과 정확한 복구 절차를 사용한다. 레지스트리를 수동으로 수리하지 않는다. 예산 연장은 현재 제한에 걸린 사용량 축이나 시간 축에 대해 완료한 것·남은 것·더 필요한 이유의 최신 근거를 요구한다. 승인된 증가량이 곧 사용 가능한 상한은 아니다. `applied`, `effective_cap`, `usable`, `park_reason`을 읽는다. 거부되면 영속 기록과 함께 사용자에게 알린다. 보류되면 정확한 clamp 필드명과 값을 제시한다. 해당 clamp의 변경이나 재탄생 승인은 사용자만 할 수 있다. 재개할 때 기록된 세션을 보존한다. revival은 사용량이나 모호성을 지우지 않는다.

독립적으로 할 일이 남지 않으면 다음 알림을 기다리며 턴을 끝낸다. 폴링하거나 sleep하지 않는다. 예상되는 상태 경계나 알림 누락·불일치에 대한 명시적인 복구에는 짧은 대기를 한 번 허용한다. 시간 초과면 턴을 끝낸다. 작업 완료와 레인·run의 닫기는 다르다. 독립 검증 뒤 안전하게 종결된 상태를 새로 입증했을 때만 닫는다.

close/reset 시에는 이 run에 기록된 요청 ID들로 `log`의 `summary` 연산을 사용하고, 레인과 자신의 실제 결과를 기대와 비교한다. 기대에 못 미친 레인에만 보고서를 통해 구체적인 원인을 묻는다. 각 레인은 자신의 friction을 직접 기록하며, 불가능할 때만 ORCH가 그 근거를 옮겨 적는다. 스킬이 원인인 friction은 `skill-review: <skill> — <cause-token>` 형식의 요약을 유지하고, 도구명에는 스킬 이름을, 기록에는 해당 track/run을 명시한다. cause-token과 kind의 대응은 wasted-context→excessive-steps, redundant-overlap→papercut, unrouted-but-used→doc-drift, trigger-mismatch→doc-drift, missing-wish→contract-gap이다. 스킬 외 원인은 일반적인 증상·근거 형식으로 보고한다. 연락할 수 없는 레인은 그렇게 기록하고 답변을 만들어 내지 않는다. 검증된 계약, 교훈, 실패 사례를 보존하고 측정값과 가설을 구분한다.

reset/handoff는 별도의 run과 ORCH 탄생을 만든다. 물려받은 주장을 재검증하고 안전하게 닫을 수 없는 원본 레인은 보존한다. 다시 시작할 때는 근거에 기반한 보존·폐기 경계와 첫 종단 간 검증 관문을 명시한다. 컨텍스트가 더 이상 책임 있는 결정을 뒷받침하지 못하면 인계 근거를 보존하고, 다음 탄생 세대를 명시한 사용자 서면 승인을 요청하며, 연속성이 있는 척 지휘하지 말고 멈춘다.
