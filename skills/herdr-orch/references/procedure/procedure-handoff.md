## 핸드오프의 책임

핸드오프는 새로운 ORCH가 대화 기억 없이도 작업 상태와 남은 판단을 이어받게 하는 일이다. 보내는 ORCH가 상태와 근거를 정리하고, 받는 ORCH가 직접 확인한 뒤 수용·보류·폐기를 결정한다. 핸드오프 문서는 다른 run의 지휘 권한이나 실행 승인을 부여하지 않는다.

## 작성과 전달

1. [[template-handoff]]를 참고해 완료한 결과, 남은 일, 사용자 결정·금지, 핵심 근거 위치, 진행 중이거나 효과가 불명확한 연산, 보존할 레인을 기록한다. 모르는 항목을 채워 넣지 말고 미확인으로 표시한다. 상황별 부록은 필요한 것만 사용한다.
2. 원본 결과를 길게 복사하지 않고 plan·assignment·report·검증 근거를 좌표와 필요한 해시로 가리킨다. 사실, 제안, 사용자 승인, 아직 검증하지 않은 주장을 구분한다.
3. 다른 run에 전달할 때는 자기 run의 `a2a/orch-to-<대상 track_id>_<대상 run_id>.md`에 요약과 인계 문서 위치를 먼저 기록하고 `herdr_message {action:"notify_run"}`으로 한 번 알린다. 알림 자체에는 내용이나 권한이 없다. 상대 run의 도구 소유 기록을 직접 쓰지 않는다.
4. 받는 ORCH는 자기 run의 `handoff.md`에 수용할 상태와 아래 주장 표를 작성한다. 상대가 전달한 문구를 곧바로 검증 완료로 취급하지 않는다. 수용·보류·폐기 결과는 자신의 plan 및 상대에게 보내는 방향별 채널에 기록한다.

## 이어받은 주장의 확인

검사 대상은 **받는 run의 `<run>/handoff.md` 안에 있는 단 하나의 `Inherited claims` 절**이다. 제목은 Markdown 2–4단계로 쓰고, 표의 열 이름과 상태 값은 영어 원문을 유지한다.

```markdown
### Inherited claims

| claim | coordinate | command | observed | disposition |
|---|---|---|---|---|
| 아직 직접 확인하지 않은 주장 | docs/evidence.md | | | unverified |
| 더 이상 사용하지 않을 주장 | | | | withdrawn |
```

- `measured`: 실제로 확인한 결과. 실행한 명령과 관찰한 커밋 SHA·시각을 기록한다. `observed` 형식은 `<40자리 SHA> <ISO-8601 시각>`이다.
- `unverified`: 아직 확인하지 않은 주장. `command`는 비워 두며 확인한 것처럼 쓰지 않는다.
- `withdrawn`: 폐기한 주장. 주장 문구만으로 기록할 수 있다.

`herdr_assignment add`는 이 문서와 절이 있을 때마다 표 문법과 `measured` 행의 SHA가 현재 HEAD인지 검사한다. 표가 없으면 이 검사는 수행되지 않는다. 도구는 `command`를 실행하거나 주장의 진위를 입증하지 않는다. SHA만 최신으로 고쳐 쓰는 것은 재검증이 아니다. 정확한 열 문법과 실패 복구는 마운트된 도구 안내를 따른다.

## 완료 경계

받는 ORCH는 첫 실행 전에 무엇을 보존하고 무엇을 버렸는지, 첫 종단 간 검증이 무엇인지 밝힌다. 보내는 ORCH는 새 ORCH가 생겼다는 이유만으로 진행 중이거나 효과가 불명확한 레인을 닫지 않는다. 레인 종료와 세션 재탄생은 각각의 안전성 검증과 필요한 사용자 승인을 따른다.
