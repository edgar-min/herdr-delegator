이 문서는 `plan.md`를 작성·확정하거나 실행 중 갱신할 때 읽는다. 구조는 [계획 템플릿](../templates/template-plan.md)을 따른다. 계획을 만드는 판단 과정은 프로토콜이 담당하고, 이 문서는 프로토콜이 바꿀 수 없는 계약만 정한다.

## 계약

- `plan.md`는 ORCH가 관리하는 현재 방향과 실행 방법이다. 실행 상태, 사용자 결정 원문, 작업 이력은 각 정본에 두고 plan은 그 위치를 가리킨다.
- 목표·경계·완료 조건은 mandate와 적용되는 사용자 결정에서 도출한다. mandate를 덮어쓰지 않으며, 후속 결정은 근거와 적용 범위를 남긴다.
- 사용자에게 유보된 판단, 작업자의 완료 보고, ORCH의 수용은 서로 대신하지 않는다. 검증 방법이 빠진 결손과 결과를 보고 내릴 판단 유보는 구분해 기록한다.
- plan 변경은 등록된 assignment, 고정 snapshot, 예산·실행 상태를 바꾸지 않는다. 계약 교정은 새 assignment로 한다.
- 계획 검토는 기본적으로 slow 프로필 레인의 적대 검토를 거친다. 생략하면 이유를 기록한다.

## 프로토콜 사용

계획 단계에서 판단이 막히면 그 결핍에 맞는 프로토콜을 실행한다. 어떤 프로토콜을 쓸지는 세션을 이끄는 모델이 현재 결핍을 근거로 선택하며, 결핍이 없으면 실행하지 않는다.

| 결핍 | 프로토콜 |
| --- | --- |
| 실행에 필요한 사실·의도·결정이 확보되지 않았다 | `inquire` |
| 목표를 한 실행 단위로 나누고 단위별 완료 조건을 정해야 한다 | `apportion` |

프로토콜은 판단과 질문을 구조화하고 그 상태를 기록한다. 실제 조사·관측·사용자 응답·계획 반영은 ORCH가 수행하며, 프로토콜의 판정이 사용자 응답이나 승인을 대신하지 않는다. 실행 결과는 `프로토콜 기록`에 연결하고, 갱신된 미정 사항·행동·완료 조건을 반영한다.

## 절차

1. 목표와 경계, 완료 조건을 작성해 사용자와 맞춘다. 이미 합의한 사항은 다시 승인받지 않는다.
2. 필요한 프로토콜을 실행해 미정 사항의 해소 경로, 실행 단위, 조건의 성격을 정한다.
3. 방법·가정·행동·의존을 작성한다. 위임할 단위는 실행 가능한 범위·입력·완료 조건이 정해진 뒤 assignment로 구체화한다.
4. 접근 권한·입력·환경·예산에서 실행 가능한지 확인한 뒤 적대 검토를 거쳐 확정하고, 지적별 처분을 `계획 검토`에 기록한다.
5. 사용자 결정, 입력 변경, 가정의 기각, 검증·수용 결과로 행동이 달라질 때 영향 범위를 확인하고 현재 필드를 교체한다. 폐기한 행동이나 해소된 대기를 남긴 채 문장만 추가하지 않는다.
6. 결과가 보고되면 완료 조건별 근거와 남은 확인을 갱신한다. 미검증 결과나 잠정 수용을 최종 완료로 바꾸지 않는다.
