# 복구, 예산, 수명 주기

복구 전에 상태를 조사한다. 효과가 입증된 지점에서 이어가고, 효과가 없었음이 입증된 뒤에만 재시도한다. 모호한 좌표는 보존한다. 마운트된 예산·revival·close 연산과 정확한 복구 절차를 사용한다. 레지스트리를 수동으로 수리하지 않는다. 예산 연장은 현재 제한에 걸린 사용량 축이나 시간 축에 대해 완료한 것·남은 것·더 필요한 이유의 최신 근거를 요구한다. 승인된 증가량이 곧 사용 가능한 상한은 아니다. `applied`, `effective_cap`, `usable`, `park_reason`을 읽는다. 거부되면 영속 기록과 함께 사용자에게 알린다. 보류되면 정확한 clamp 필드명과 값을 제시한다. 해당 clamp의 변경이나 재탄생 승인은 사용자만 할 수 있다. 재개할 때 기록된 세션을 보존한다. revival은 사용량이나 모호성을 지우지 않는다.

독립적으로 할 일이 남지 않으면 다음 알림을 기다리며 턴을 끝낸다. 폴링하거나 sleep하지 않는다. 예상되는 상태 경계나 알림 누락·불일치에 대한 명시적인 복구에는 짧은 대기를 한 번 허용한다. 시간 초과면 턴을 끝낸다. 작업 완료와 레인·run의 닫기는 다르다. 독립 검증 뒤 안전하게 종결된 상태를 새로 입증했을 때만 닫는다.
