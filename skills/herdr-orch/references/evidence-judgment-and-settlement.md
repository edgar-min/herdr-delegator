# 근거, 판단, 종결

작업자가 완료나 차단 등의 상태 경계를 보고하면 짧은 완료 요약과 조건별 근거 표만 읽고, 권한 검사를 거치는 관찰 연산을 사용한다. 응답에 부착된 settlement 판정을 검토한다. 미해결 공백이 있으면 인용된 범위만 읽고, 보고서 전체를 읽지 않는다. 완료 파서가 성공했거나 모델 점수가 높다고 정확성이 입증되는 것은 아니다. 조건별 수용 근거, 경고, 필요한 복구를 기록한다. 잘못된 형식의 완료 보고는 작성자에게 정확한 수정 방법을 전달한다. 대신 고쳐 주지 않는다. `blocked`는 작업을 종결시키지 않는다.

공유 작업 트리에서는 변경 경로의 귀속이 구조적으로 모호하다. 다른 레인의 커밋이나 인덱스에 별개 레인의 변경 hunk가 들어갈 수 있다. 이런 관찰은 조사해야 할 귀속의 모호성으로 다루고, 작업자의 잘못으로 단정하지 않는다.

해시 등으로 고정한 작업자 산출물을 바탕으로 별도의 임시 루트에서 하네스 실행과 독립 재현을 위임한다. 증거를 직접 만들어 내지 않는다. 실제 결과를 완료 조건, 적용 맥락, 빠진 가정, 대안과 비교한다. 사실 주장에는 직접 관찰이나 원천 자료를 확보한다. `check`는 제공된 참고 자료의 지지를 찾을 뿐 진실을 판정하지 않으며, 원천에서 직접 읽을 수 있는 사실에 대한 두 번째 의견도 아니다. 평가에는 독립적인 기준 사실을 요구한다. 중요한 인계가 불명확하면 독립적인 검토를 사용한다.

불확실한 사안을 사용자에게 올리기 전에 결정 사항과 알려진 맥락으로 `judge`의 `escalate` 시점을 호출한다. 기존 권한으로 확정되는 것은 스스로 결정하고, 도구가 답할 수 있는 것은 관찰하며, 진짜 사람의 판단이나 사용자에게 유보된 승인만 요청한다. 명시적인 승인은 판정과 무관하게 필요하다. 호출 실패가 권한을 부여하지 않는다. 실제로 수용·수정·기각한 결과는 반환된 요청 식별자로 `log`의 `outcome` 연산에 기록한다. 문서 본문을 넣지 않는다.
