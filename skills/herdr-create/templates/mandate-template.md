# mandate 입력 작성 예시

생성자 세션은 아래 구조의 값을 `herdr_track`의 `action: "open"`에 전달한다. 렌더러가 이를 받아 `orchestrator-instructions.md`를 만든다. 이 문서는 **입력 작성 참고 자료**이며 렌더러가 읽는 실행 템플릿이 아니다. 생성자가 run 파일을 직접 작성하지 않는다.

## 필드와 값

| 필드 | 입력 종류 | 작성 방법 |
|---|---|---|
| `intent` | 문자열, 필수 | 사용자가 원하는 결과와 이유를 적는다. WHAT/WHY만 담고 구현 방법이나 작업자 배치 계획은 넣지 않는다. |
| `constraints` | 문자열 배열, 필수 | 금지, 필요한 승인, 범위 등 합의된 경계를 항목별로 적는다. 확정된 제약이 없으면 `[]`를 전달한다. |
| `shape_of_success` | 비어 있지 않은 문자열 배열, 필수 | 무엇을 관찰하면 완료인지 적는다. 트랙의 권한과 사용 가능한 수단으로 달성하거나 확인할 수 있는 조건을 사용한다. |
| `budget` | 객체, API에서는 선택 | 이 스킬에서는 `tokens`와 `minutes`의 추정치를 모두 명시한다. 생략 시 도구의 기본값이 적용된다. |
| `budget.tokens` | 양의 정수 | run 전체의 토큰 추정치. 고정 정답이 아니라 연장 판단의 출발점이다. |
| `budget.minutes` | 양의 정수 | 경과 시간의 추정치(분). 토큰과 별도 축으로 관리된다. |
| `budget.doorbell_policy` | `"notify"` 또는 `"full"` | `notify`는 기계 감사가 연장을 판단하고 사용자에게 알린다. `full`은 사용자 승인과 사용자 소유 clamp 조정이 필요하다. 사용자 요구에 맞춰 선택한다. |

문자 수, 항목 수, 정수 상한과 기본값은 마운트된 도구 스키마를 따른다. 이 예시를 별도의 한도 정의로 사용하지 않는다.

## 전체 호출 예시

아래의 트랙 이름·경로·내용·예산 수치는 구조를 보여 주는 예시다. 실제 대화에서 합의한 값과 프로젝트 경로로 바꾼다. 예시의 예산을 기본값처럼 복사하지 않는다.

```json
{
  "action": "open",
  "track_id": "search-review",
  "run_id": "r1",
  "cwd": "/absolute/path/to/project",
  "mandate": {
    "intent": "검색 결과가 누락되는 원인을 확인하고, 사용자가 개선 방향을 선택할 수 있도록 근거와 대안을 정리한다.",
    "constraints": [
      "저장소 코드를 수정하지 않는다.",
      "외부 서비스에 데이터를 보내려면 먼저 사용자 승인을 받는다."
    ],
    "shape_of_success": [
      "보고된 누락 사례의 재현 여부와 확인한 근거가 기록되어 있다.",
      "원인 후보, 검증 결과, 남은 불확실성과 개선 대안이 구분되어 있다."
    ],
    "budget": {
      "tokens": 120000,
      "minutes": 60,
      "doorbell_policy": "notify"
    }
  }
}
```

`track_id`, `run_id`, `cwd`는 run 좌표와 작업 위치이고 mandate 본문 필드가 아니다. 렌더러는 좌표를 문서 머리말에 넣고, 네 mandate 항목을 각각 Intent, Constraints, Shape of success, Budget 절로 렌더링한다. 계획은 새 ORCH가 사용자와 대화하며 별도의 `plan.md`에 작성한다.
