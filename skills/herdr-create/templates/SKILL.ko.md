# Herdr 트랙 생성 — 한국어

`herdr_track open` 도구를 사용하여 새로운 트랙을 생성하며, 그 트랙은 별도의 오케스트레이터(**ORCH**)를 갖게 된다. 이 스킬을 실행한 세션은 "생성자 세션"이 된다.

새로운 트랙을 개설할 때는 아래 사항을 고려한다. 

## 트랙이 도움이 되는지 판단한다

지속적인 컨텍스트 유지가 필요한 작업, 서로 겹치지 않는 소유권이나 의존 관계, 오래 보존할 근거, 또는 별도로 생성된 ORCH에서의 복구가 필요하면 트랙을 연다.
지속적으로 유지할 책임이 필요 없는, 범위가 한정된 작업은 현재 세션 또는 다른 세션에서 처리한다.
절차를 늘리기 위해 불필요한 트랙을 만들지는 않는다.

## 범위가 한정된 mandate를 추출한다

이미 나눈 대화에서 핵심을 추출하며, 합의된 내용을 다시 묻지 않는다.

mandate에는 **무엇을(WHAT)** 할지와 **왜(WHY)** 하는지만 담는다.

- `intent`: 트랙이 존재하는 이유와 달성해야 할 것을 사용자의 표현으로 적는다.
- `constraints`: 필요한 승인을 포함해 ORCH가 넘어서는 안 되는 경계를 적는다. 단, 확정되지 않은 제약을 임의로 가정하지 않는다.
- `shape_of_success`: 트랙을 완료로 볼 수 있는 관찰 가능한 조건을 적는다. 트랙의 권한과 사용 가능한 수단으로 달성하거나 확인할 수 없는 조건을 요구하지 않는다.
- `budget`: 예상 토큰과 분을 모두 선언한다. 둘은 별도의 상한이다.
  사용자의 승인 요구에 맞춰 연장 정책을 선택한다. 기본값, 한도, 사용자만 변경할 수 있는 제어 항목은 마운트된 스키마를 따른다.

**어떻게(HOW)** 할지는 넣지 않는다. 계획, 작업 분해, 작업 배정과 구현은 새로 태어난 ORCH의 책임이며 `plan.md`에서 다룬다.


## 최초 open 호출은 한 번만 한다

프로젝트 작업 디렉터리와 추출한 mandate를 사용해 `action: "open"`으로 최초 `herdr_track` 호출을 한 번 한다.
이 호출을 통해 자동으로 생성되는 운영 지시문과 함께 새로운 트랙이 시작된다. 

run 파일을 직접 구성하거나, 오케스트레이터를 별도로 실행하거나, 도구 소유 상태를 편집하지 않는다.
open이 실패하면 임의로 수습하지 않고 반환된 복구 지침을 정확히 따른다.
동일한 호출의 재시도는 그 지침이 지시할 때만 허용된다.

## 안내한 뒤 역할을 끝낸다

트랙 생성이 성공하면 반환된 `next_step`과 사용자가 어디서 어떻게 계속할지에 영향을 주는 안내를 사용자의 언어와 말투로 전달한다.

그 뒤에는 생성자 세션이 새 트랙의 ORCH가 그 작업에 대해 온전한 책임을 가질 수 있도록 해당 트랙과 관련된 작업에 개입하지 않는다. 
해당 주제에 대해서는 사용자가 새로 태어난 ORCH와 이어나갈 수 있도록 안내한다.
